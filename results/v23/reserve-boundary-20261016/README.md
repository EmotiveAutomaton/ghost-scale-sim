# V23 first-burn-in and reserve checkpoint

R3's recovered first burn-in passes independent numerical reconstruction. Its
calibrated card still requires the second burn-in; no terminal family result is
claimed. N2's second batch has one complete partition, with its parent still active.

- `R3_NUMERICAL_REVIEW.json`, `R3_MACHINE_CARD.json`, `R3_CURVE.json` and
  `R3_DIAGNOSTICS.json` retain the complete first-burn-in evidence.
- `BINDINGS.json` authenticates the existing R3 reconstruction, its controller
  source and prior execution audit, plus the newly checked N2 partition.
- `RAW_HASH_INDEX.json` retains the R3 indices and all 1,119 N2 partition files.
  R3's earlier execution audit is reused under exact hashes; no science was repeated.
- `CAPACITY.json` records charged and reserved cost, including the unstarted N3
  burn-in reservation. R3's second batch is deferred, not forgiven.
- `REVIEW.json` separates this boundary from a terminal family review or confirmation.
