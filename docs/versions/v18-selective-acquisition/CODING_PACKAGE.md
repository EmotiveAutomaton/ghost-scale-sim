### Acquisition and information

Use 32 offered opportunities with 16 cues for each of two topics. A constructor permutes the four cells into two disjoint two-action motifs, A and B, and supplies the inherited teacher/student reliability parameters. Preserve actual execution errors rather than assigning acquired expertise directly.

All learners get the same instruction: prepare to use focal topic A. Before processing, they see only the offered topic cues. Processing exposes the instruction, performed actions, observed endpoint and accurate binary success feedback. Keep instruction and feedback enabled in every condition; they are not additional factors this weekend. The intended source target stays evaluator-private except for the admitted success feedback.

Compare two selections from the same offered pool:

- **Broad:** first eight offers of each topic in the seeded offer order.
- **Focused:** first twelve A offers and first four B offers.

Both process sixteen distinct offers. The 8/8 broad arm is a new comparison; the old K05 code used 12/4 versus 4/12. Record the selection before outcomes are exposed. For a given offer and history, the performed action trace must be identical wherever that offer appears in an arm. No outcome-dependent substitution or repeated offer to fill a quota.

Use `learn_processed` unchanged in its scientific rule: count eligible repeated performed programs, exclude explicitly failed attempts, require at least three repetitions, retain the highest-count two-action fragment with the inherited deterministic tie break. An empty library is a legitimate result. Store ties and learned-library identities; fixed tie breaking and action ordering can matter in this tiny world.

This is deliberately a capacity-one repeated-fragment learner. Its count-based compression and assigned focus are implementation assumptions. Do not claim that it models all human expertise or that competition for its single slot establishes inevitable contamination.

### Transfer targets and checking

Only after acquisition, disclose the actual construction goal to every arm. Use two prespecified target strata:

1. **Compatible composition:** A's two cells plus one B cell. Score both B alternatives. These three-cell endpoints were not acquisition targets.
2. **Changed composition:** one A cell plus one B cell. Score all four cross-pairs. These endpoints were also not acquisition targets. A complete learned A or B motif can now introduce an unwanted cell.

The second stratum tests transfer across a changed requirement. It does not claim that attention already had access to the later goal and ignored it. Differences between strata also include target size; interpret policy effects within each stratum against its matched primitive baseline, not a raw success difference between strata as a pure goal-change effect.

Cross the two acquisition rules with two use policies:

| Policy | Acquires | Uses |
|---|---|---|
| Broad / unchecked | 8 A, 8 B | Ordinary acquired fragment |
| Focused / unchecked | 12 A, 4 B | Ordinary acquired fragment |
| Broad / checked | Same broad acquisition | Fragment retained only after paid local checking |
| Focused / checked | Same focused acquisition | Same paid checking rule |

For checking, reuse the explicit `inhibition` rule: execute each candidate fragment from the declared initial state, inspect legality and each step's Hamming-distance change relative to the **now-public own target**, and discard a fragment with an illegal or locally worsening step. All arms know the target and public transition law. Only the checked policy spends work on this preliminary screen. It receives no private source purpose or unseen outcome.

This is a particularly capable, exact local check. Describe it as such. The world does not establish that people can inspect dependencies this precisely. A locally worsening step can be necessary in richer tasks; the four-cell result supplies no general argument against such detours. Record that limit rather than inventing an assembly study during setup.

### Costs and cheap rivals

Start with a **32-primitive execution envelope per transfer target**, shared between checking and search. Deduct actual checking cost before `construct`. Final submission execution is recorded separately for every arm. Do not charge a checked arm extra and then label the primary comparison matched-budget. Do not call this matched total computation: acquisition, instruction/feedback queries, learning, storage and wall/CPU time must also be itemized.

The acquisition dose is identical across arms, but retain its actual processing and feedback costs. An offer scan is not a processed example. Never invoke `learn(attempts, targets)` with private targets to recompute unavailable feedback; the admitted binary feedback is sufficient for the chosen learner.

Run a **primitive-only baseline** on every same target and budget. Also report the two checked policies at the original full search budget as a labelled extra-cost diagnostic, with the checking cost charged in the ledger. The first comparison asks whether checking pays within a resource limit; the diagnostic asks whether a lost benefit is caused by spending that limit on checking.

Useful transfer is successful execution at the learner's own target. Interference is loss relative to primitive-only execution, or increased search/execution cost for comparable success. A source routine that merely exists is not a harmful influence. A safe timeout is search failure, not an enacted wrong belief or adopted value. Retain first proposals, final submissions and actual executed endpoints separately.

The no-library baseline is also the paired removal diagnostic for this capacity-one learner. It isolates the consequence of having that representation in this solver; it does not identify a uniquely psychological cause.
