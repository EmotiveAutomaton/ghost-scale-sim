# V18.1: acquisition, dependencies and recoverable process

The unchanged [commission](CODING_PACKAGE.md) extends the questions after the
completed original V18 study. Original sources, run clocks and findings remain
closed. This directory owns V18.1's design, admissions, branch decisions and report.

## DESIGN CHECK

Question: does focused acquisition help because of what is learned, memory capacity
or retrieval/search, and which evidence allows useful but temporarily worsening
methods to be used and their actual production history to be recovered?

G0 first replays original cases as an exposed diagnostic, crosses memory and paid
checking, and introduces equally informed common state search and episodic rivals.
G1 verifies native necessary detours before scoring gates under correct, incomplete
and misleading dependencies. G2 learns dependencies and selects observations with
held-out prediction and execution scores. G3 varies laws/topologies across three,
five and seven parts and retains the graphic family as a separate check. G4 tests
recoverable process and supplies a separate blind reader/evaluator packet.

The independent unit is a concrete law/topology and acquisition context. Histories,
label permutations, action orders, budgets and methods are nested comparisons, not
independent architectures. Enumerate finite native support. Reserve unused evaluation
namespaces. All initial branch results are descriptive; at most two final contrasts
may be frozen after discovery and evaluated on untouched structural units.

Every reader uses a strict serialized public contract. True laws, generating paths,
source intentions and evaluator outcomes are private unless an explicitly named
ceiling receives them. Incorrect model predictions execute against the true law;
invalid donors are retained. Reachability, stopping and depth bounds are checked
independently. Paid selection/checking/search/final execution share the main online
envelope; original V18 primitive-budget diagnostics retain their separately named
historical convention. Acquisition and storage are separate charged quantities.

Validity admission precedes each source-frozen branch revision. Known-answer tests
cover positive/negative execution, native agreement, necessary detours, observation
equivalence, private-field swapping, total-cost limits, depth-aware deduplication,
source/receipt corruption and interrupted resume. Every completed block retains
replayable inputs/outputs and immutable checksums. Full aggregates are reconstructed
from retained output; larger physical replays use a frozen bounded selection.

## Ownership and operation

- `ghostscale/validation/soundingline/v18_1/`: new adapters; closed helpers unchanged.
- `runners/run_v18_1.py`: source-bound blocks and native ownership.
- `results/v18/continuation/`: public plans, branch dispositions, proof and summaries.
- Outer `.local/v18-1/`: raw blocks, pinned revisions and machine-local operations.
- Codex in this commissioning conversation: admission, branch allocation, final
  analysis and documentary write-through. Native supervision does not invent science.

One low-priority CPU worker, numerical threads limited to one, no GPU/cloud or
environment synchronization. The new immutable acceptance clock starts at the first
recorded startup observation on 18 September. Report preparation begins 20 September
13:00 UTC; delivery is 15:00 UTC. Ceiling: 40 worker-process CPU hours including child
compute and 200,000 new law/context units. Progress decisions fall at 4, 12, 24 and
36 elapsed hours. Native supervision wakes on transitions; healthy computation does
not require periodic model polling. A drained initial block is not campaign closure.

Current status is recorded in the branch ledger, not inferred from this design.
No outcome in a planned branch is claimed before that branch is executed and checked.
