# Unknown-time purpose and skill changes

Does the filtering benefit survive withholding the possible change time and the
factor that can change? This implements the prepared B-family discriminator.
All readers still receive the exact endpoint law. This is an oracle-law reference,
not learned detection or historical local-process recovery.

Use the eight original admission lineages 190000–190007, all sixteen makers
equally, observation draws 190201/190202, lengths 32/128, independent/duplicated
sources and purpose/skill change types separately. Each type crosses no change
and one complement after observation 16/64. No-change streams for the two types
are identical paired controls, never extra independent observations. Reuse the
previous common uniforms and rotating context schedule. Duplicate sources retain
their original time and count once. Retain all original native paths. Independently
reconstruct their legal operations, probabilities and full transient state before
using skill-change endpoint laws. No fit, new seed or reserved lineage is used.

Five arms see each stream: static; last sixteen distinct sources; coherent mixture
with supplied time and type; unknown-time mixture with supplied type; and a mixture
with both time and type unknown. Each mixture assigns half its total prior to no
change and half to a single change. Unknown times are uniform over every integer
from 8 through length minus 8 inclusive. The unknown-type arm divides change mass
equally between purpose and skill. All begin with uniform maker priors. Complete
hypotheses retain initial maker, change time and type; there is no pruning or
multiplication of independent factor marginals. A possible future change does not
remap current state until its hypothesized time. The declared horizon and allowed
change family remain supplied information. Actual planted changes occur at the
middle; this is not a test over all possible actual times.

Freeze each lineage's complete observation roster before any filter execution.
Use the previous checkpoints: 8/16/17/20/32 and 16/32/64/65/80/128. Save the full
joint hypothesis weights as compressed float64 arrays, with explicit row and
hypothesis mappings, alongside current-state probabilities and forecasts. Keep
endpoint logarithmic loss, true-state logarithmic loss, true-state mass, 90%
credible-set inclusion and set size distinct. The 1e-300 reporting floor and
1e-14 boundary-tie rule remain unchanged. Endpoint loss predicts a fresh episode
under current state, not across a future change. No retrospective path claim follows.

Pair all five arms within maker, draw and lineage. Keep change type, switch status,
length, source condition and checkpoint separate. Average draws within lineage;
use 10,000 paired lineage bootstrap resamples, seed 190501, and the frozen 0.02-nat
endpoint margin during independent numerical review. Never pool the identical
no-change type controls to claim more precision. Type-posterior mass is a diagnostic
of the stipulated candidate family, not calibrated real-world cause identification.

Before admission, controls must check direct hypothesis-product enumeration,
prior mass by type/time, future-switch remapping, duplicate identity and rejection,
uninformative uniform current state, known-type identity with the earlier filter,
both purpose and skill involutions, empty-support rejection, native legal-tool
support, binary joint archive replay and reader/evaluator separation. The separate
four-CPU-hour card includes failed attempts, tests, original execution, adjacent
and extracted-source replay and independent review. Complete reproducibility is
required before numerical acceptance; immutable source admission precedes dispatch.

Reader exports contain observed contexts/endpoints/source identities only. Type,
actual change assignment, supplied law, maker, pairing labels, hypotheses, forecasts
and scores stay in evaluator exports. Duplicate streams have fewer distinct sources;
their differences do not isolate a pure dependence effect.

## Two independent prepared alternatives

Changed-tool learned support transfer remains a four-hour F-family alternative:
both saved count fits, original and changed tools, shared 1/32 final smoothing,
direct lookup, exact learned propagation and sixteen rollouts, with wrong-law
and native legal-support controls. Freeze all source/input bindings before use;
no new architecture or fit setting is authorized by this design.

A four-hour E-family support diagnostic reuses both completed practice count
learners at 32/128/512 episodes. Evaluate their frozen production policies on
each of the four original contexts, retaining context-specific native success
and visitation counts. Compare matched and restricted-start training without any
new update. Independently reconstruct every table from saved ordered episodes,
verify exact replay identity and untouched-context prior, and report whether the
support-mismatch penalty localizes to the unvisited context. Equal-context and
original training-distribution summaries must remain separate. This needs its
own implementation, known-answer controls and frozen admission. Neither alternative
depends on an unknown-change filtering advantage; neither is currently queued.
