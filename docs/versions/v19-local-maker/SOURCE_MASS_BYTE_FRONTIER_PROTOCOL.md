# Retained source probability per byte: prepared independent alternative

How much supplied source probability can a fixed memory budget retain? Equal
source counts can have different costs, so highest-probability selection at a
fixed count does not resolve the memory allocation question. This alternative
measures a storage frontier, not future prediction or historical correspondence.

Use every existing source roster and its structural group/past-state table costs
from the accepted fixed-byte retention population. Freeze uniform,
time-proportional and reciprocal-time weights. Freeze the two existing byte
budgets derived from recent half and quarter retention. Count fixed state,
remainder and source metadata consistently with the weighted remainder schema;
do not silently compare a uniform-prior state with a differently encoded prior.

At each budget compare recency, descending source probability, descending
probability per incremental byte and an exact finite knapsack optimum. Greedy
policies skip an item that does not fit and continue. Break all ties by recent
time. For optimum ties, use lexicographic preference over the sorted recent-time
bit vector. All choices depend on declared source weights, structure and bytes,
never endpoint likelihood, goals, measured forecast error or future outcomes.

Retain complete selections, exact integer byte counts, supplied retained mass,
unused capacity and gaps to the finite optimum. Preserve zero-cost items and
empty/full budgets explicitly. Validate small cases by independent exhaustive
subset enumeration, plus permutation, equality, an intentionally suboptimal
greedy case and corrupted-cost controls. A mass optimum is not a prediction
optimum. Report equal-law paired summaries while preserving both source draws.

Prepared, unimplemented and unadmitted. All saved rosters remain in scope; no new
fit, observation, protected lineage or forecast experiment. Require complete
support timing and a frozen source/plan before native admission. The inclusive
1,800 CPU-second cap includes controls, failures, original and both complete
replays, independent reconstruction and original-row regroup within the existing
family/global limits. Dynamic programming is an implementation candidate, not
an already admitted handler.
