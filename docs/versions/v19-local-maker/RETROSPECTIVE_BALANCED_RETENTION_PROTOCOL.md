# Context-balanced retention: prepared independent alternative

At the same retained-source count, does coverage of query contexts preserve more
retrospective information than recency? This alternative is unimplemented and
independent of a favorable forgetting result. It uses the same retained complete
posteriors, source identities, eight laws and both evidence conditions and draws.

For each half and quarter time-window count, compare recency with a deterministic
context round-robin roster. Cycle context labels 0,1,2,3, taking each context's most
recent unselected source, skipping exhausted contexts, until the same source count
is reached. This outcome-blind selection retains every source's original prior
mass in either exact joint state or the explicit remainder. Never select by hidden
maker labels, endpoint informativeness or observed score. Include a global context
label permutation sensitivity check: the label order is a declared tie-breaker,
not a claim of optimal design. Report actual mixed-cell and shared-index storage,
since equal source counts need not give equal bytes.

Enumerate all eight endpoint reports and five copying probabilities. Compare
expected squared-loss regret and largest future-probability error, support failure
and storage separately. Keep all paired identities and class/evidence strata.
Known-answer controls include equal selected-roster identity, single-context
identity, an older informative context, exact remainder mass and source-order
permutation with timestamps unchanged. Independent scalar reconstruction and two
complete replays are required; no new fit or protected lineage.

Before native outcomes, freeze implementation and complete-support synthetic timing
under a prospective 3,600 CPU-second inclusive cap within existing family/global
limits. If full support is intractable, record the blocker rather than sample
favorable sources. Two-report dependence remains independently prepared.
