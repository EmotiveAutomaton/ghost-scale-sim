# Optional field disclosure: prepared alternative

Does allowing a reader to decline an unhelpful request improve the net value
of mechanically available metadata? The fixed one-field comparison always pays
for a field even when visible evidence already settles the endpoint. This
follow-on is prepared before its outcomes and adds no sampled evidence or fit.

Use the same complete 640-query roster, eight retained laws, both tools and
uniform-legal versus native conditional laws. For each visible group, compute
the largest expected endpoint-entropy reduction from skill or belief. Request
that field only when the reduction strictly exceeds a price of 0, 0.02 or 0.1
nats; ties between fields prefer skill and ties with price decline. Compare
no request, forced entropy-selected request, optional entropy-selected request,
and an equal-rate query-independent request policy using exact expected scores.
The latter retains the optional policy's overall request rate within law/tool,
but allocates it uniformly across visible groups under the scored population.
Report selection rates, actual logarithmic loss, net cost, residual ambiguity,
and native versus equal-query weighting separately. A law-based expected benefit
is not guaranteed optimal after switching the evaluation population.

Keep policies constant within visible groups and exclude individual hidden
fields or endpoints from selection. Require constant-endpoint/no-request nulls,
known informative fields, price and field ties, probability normalization,
zero-support fallback, exact score-mixture checks and deliberate target leakage.
Freeze a finite manifest and source before execution; independently reconstruct
all results and replay before acceptance. The current state is prepared and
implemented pending isolated controls and source admission. The cap is 0.5 CPU hour including controls, original, replay and
review within the unchanged F/global allocation. It is independent of the
retrospective quotient alternative. This is an oracle value-of-information
method comparison; it cannot establish learned access or human intent.

The matched-rate control uses the same frozen visible-group field choice as
the optional policy; only whether to request is randomized, independently of
query identity. Its constant request probability equals the optional rate under
each scored population. Average request and no-request proper scores exactly;
never score an averaged forecast. Selection uses the original frozen entropy
values and literal strict price comparison. Parent field choices at numerical
entropy ties are retained and qualified, without a post-outcome rule change.
All price-specific probabilities and field choices are evaluator records.
