# Primitive input pooling: complete replay verified

We tested whether pooling equivalent tool inputs improves a frozen forward model. All 433 deterministic outputs match across the original and both complete replays. The constructed-method comparison retains 640 queries and 983,040 paired score rows; independent numerical acceptance remains pending. No predictive advantage or historical process correspondence is accepted yet.

Both saved training draws and original/composition-holdout support modes retain
all 640 queries and eight paired development lineages. Original/changed tools,
forward/reverse input orders, truthful/bit-flipped reports and budgets 0/16 are
crossed with unpooled, undo-buffer-pooled and wrong current-artifact-pooled tables.
The 192 model/forecast comparisons contain 122,880 forecast vectors, 983,040
paired score rows and 46,080 aggregate strata. These repeated rows are not
independent worlds or feedback samples. No new fit or held-out lineage is used.

Both pooling maps merge eight inputs at a time and affect only skilled accept-
tool rows. Empirical counts subtract each saved unit prior before aggregation;
one unit prior per outcome is restored per group. Every distinct complete input
adds one count, even when multiple inputs share a group. Exact duplicate reports
count once and conflicting duplicates are rejected. The wrong map may aggregate
different outcomes from distinct inputs; that conflict is retained as data.
Undo operations and all other rows keep their full transient input.

The zero-feedback comparison isolates this supplied representation change. The
matching unpooled arm reproduces the previously validated one-count feedback
method; no row-replacement result selected this update. Skill, belief and complete
operation-query metadata remain supplied privileges. Every forecast uses the
same final 1/32 smoothing. Native and equal-query populations, changed/stay
outcomes and original support strata remain distinct.

Original, adjacent and extracted-source runs reproduce all 433 deterministic
outputs. All 515 source files, 33 frozen inputs per execution, source archives,
plan/environment identities and output hashes verify. Eight internal controls
include known/wrong semantics, one prior, duplicates, undo preservation and full
path sums. The original admission has ten isolated tests including runtime and
portable dispatch. Complete replay establishes reproducibility, not an accepted
numerical advantage.

The independent checker now has 519 frozen source files and 436 input files,
with ten passing isolated controls. It rebuilds each destination/outcome count
by scalar summation across its complete class, independently of the producer's
group accumulator. It reuses the separately validated reviewer's executor and
explicit path sum. It checks all tables, forecasts, scores, native masses,
support labels, public projections, group maps and denominators. Corruption
controls cover counts, tables, forecasts, losses, maps, groups, masses, reader
fields and stratum counts. Parent training and path probabilities inherit their
separate validated reviews; the checker does not refit them.

Its frozen regroup averages both saved fits inside each of eight paired
lineages and uses 10,000 paired resamples. It reports each draw separately and
compares pooled versus unpooled, feedback versus the same arm without feedback,
wrong versus truthful reports, and reverse versus forward order. The 0.02-nat
margin is unchanged. Equal-query forecasts repeat across lineages; degenerate
conditional intervals do not measure training or feedback-population uncertainty.

**Warrant:** execution and complete replay verified; numerical outcome remains
inconclusive pending independent review. This is a constructed-method comparison,
miniature — architecture untested. It does not establish a learned equivalence,
historical process correspondence or human intent. Forty-three earlier scientific
batches retain acceptance; this batch has not increased that count.

**Pursuit:** complete independent numerical reconstruction under the existing
serial queue and two-hour pooling cap. Retrospective evidence after future-
schedule grouping and the hidden-metadata boundary remain independently prepared,
unimplemented alternatives under their unchanged one-hour B/two-hour F caps.
The global 96-hour cap and protected 16 hours remain unchanged.
