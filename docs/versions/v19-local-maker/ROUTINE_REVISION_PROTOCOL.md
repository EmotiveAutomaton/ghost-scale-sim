# Prior routine, current request and a fixed revision opportunity

Does an artifact that misses the current request reflect an unchanged productive
routine, limited operations, or failure to use a revision opportunity? This is a
finite policy comparison, not a learned expertise or human endorsement test.
It advances the independent alternative prepared before the support result.

Reuse all 13,824 retained three-operation trajectories on each original admission
lineage 190000–190007. Preserve their native probabilities, sixteen makers, four
contexts, governing purpose, skill, belief and routine. The original episode and
its goals are unchanged. After its third operation, expose a separate one-operation
revision opportunity. Its undo buffer is the artifact before the third operation.
Cross the original request with its truthful binary complement, and intact
inspection with inspection hiding presentation in both current and undo artifacts.
The request is observed; adopting it is an explicit intervention, never inferred
from an action. No new generator draw or reserved lineage is used.

Freeze five policies before execution:

- Keep the produced artifact, with no inspection or revision cost.
- Native policy: retain the maker's governing purpose and routine; use the native
  third-position goal/operation policy with the new request. Reusing that position
  retains the native dependency-goal undo alternative. This is a single revision,
  not a fourth step silently added to the admitted primary episode.
- Request-adopted policy: the same policy and routine, replacing only governing
  purpose by the current request. Goals are still selected before operations.
- Visible-task reference: given skill/belief execution mechanics, choose the legal
  operation maximizing expected task success minus operation cost. Hidden current
  and undo presentation bits are independent fair bits, declared as a reference
  prior. All exact ties share probability equally, with tolerance 1e-12.
- Full-state task oracle: the same optimizer, supplied the actual current artifact
  and undo buffer. Neither optimizer is a learned maker or a goal-labelled policy.

The available operations are the six existing operations; accept-tool is illegal
for the unskilled maker. Execution mechanics never change with request adoption.
Functional success means claim and evidence both on; presentation success means
the display unit is on. The current request selects which success is scored.
Inspection costs 0.01 success units for every revising policy. Inspect/keep has
zero operation cost; every other operation costs 0.05, including undo. Those are
stipulated task costs, not measured human values. Report success, net success,
operation cost, revision rate, repaired failure and destroyed success separately.
The native policies do not consult presentation when choosing; hiding it is an
identity control for their decisions, not a promised effect.

Collapse only identical full revision states (maker, current artifact, undo
buffer, original request), summing native path weights and retaining every source
index in evaluator records. Save each policy's full distribution and every
operation outcome. Regroup by lineage, changed request, observation, original
purpose, skill and routine; preserve all strata, not only a pooled result.
The initial report is descriptive. Paired intervals use 10,000 lineage resamples,
seed 190501; 0.02 absolute success units is the predeclared practical margin for
this task comparison. No positive result automatically authorizes confirmation.

Controls precede scientific inputs: exact undo, illegal tool rejection, request
adoption changing goal probabilities, observation identity for the native policy,
hidden-bit invariance of the visible reference, intact reference/oracle identity,
known task improvement, unchanged keep, and oracle dominance under declared costs.
Tests exercise the complete handler on a synthetic non-campaign fixture. Freeze
source, environment, protocol, inputs and plan before serial admission. A complete
adjacent replay and extracted-source replay follow the original in the existing
queue. Independent numerical review precedes scientific acceptance.

The reader archive contains deduplicated observed revision packets and unit
anchors only. Maker attributes, adopted-policy identity, latent goals, probabilities,
pairing, full artifacts, reference inputs and scored outcomes are evaluator-only.
Skill/belief inputs of the task references are explicitly privileged and cannot
be attributed to an ordinary reader of the anonymous packet.

This card allows four CPU hours including fixtures, all executions and review,
inside the existing E-family and global exploration ceilings. It consumes no
tiny-model setting, no new training draw and no protected lineage.
