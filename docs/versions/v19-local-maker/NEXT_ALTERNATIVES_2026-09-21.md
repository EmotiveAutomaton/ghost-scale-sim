## E2: task and skill under incomplete observation

Question: does an apparent artifact error depend on the maker's objective, and
does hiding a dependency obscure that distinction? Reuse the eight admitted local
worlds and their complete retained trajectories, with no additional sampling or
new local-goal labels. Compare the two existing governing purposes and both skill
levels while marginalizing belief error and routine with equal declared weights.

Before execution, freeze two evaluative functions: functional success requires
claim-on and evidence matching the claim; presentation success requires display-on.
These functions are declared evaluative choices, not newly discovered intentions.
Report both functions for every purpose/skill stratum instead of selecting the
function that favors a result. Include their joint success and disagreement mass.

Compare intact final artifacts with a deterministic projection hiding the evidence
unit. Keep requested purpose distinct from actual purpose: the initial context and
request form a second declared evidence tier. The exact conditional reference
and uniform compatible-template baseline consume identical visible projections.
Report governing-purpose loss, candidate coverage and abstention separately from
artifact success. No fitted reader or verified production skill is supplied by
this diagnostic, so it cannot establish a practice or expertise benefit.

Use complete probability-weighted enumeration within each of the eight lineages;
pair intact/degraded conditions and objectives within lineage. Validate mass and
projection consistency, a no-information purpose fixture, an identifiable-purpose
fixture, and the fact that the degraded projection cannot improve exact expected
conditional logarithmic loss. Export visible content without lineage or maker
identifiers; retain trajectories, posterior targets and evaluative functions in
the scientific/evaluator role. Initial E2 cap remains four CPU hours inclusive of
implementation checks and complete replays. If objective ranking reverses, move
to the named new-dependency discriminator; otherwise record a bounded negative.

## B2: accumulated error versus privileged one-step training

Question: if B1 shows accurate teacher-forced updates but degraded free-running
forecasts, does training on the model's own preceding states reduce that drift?
Retain B1's observable endpoint teachers and one-step baseline. Freeze a two-pass
rolled-in schedule before fitting: fit the existing one-step head, generate its
own training-stream states without using development outcomes, then fit one new
head to the same observable teachers and number of new-source prefixes. Count
both fitting passes and retained examples explicitly; include a two-pass exact
teacher refit as the computation/control arm. This resolves a named input-shift
rival, not an equal-training-privilege claim.

Use the original paired lengths 8 and 32 before extending to 128. Extension needs
a new source-bound manifest with the same eight development lineages and a
declared stream-generation rule; it is not seed padding. Keep copied-source skip
controls, cached/full-history identity, teacher-forced and free-running results
separate. If B1 lacks a teacher/free-run gap, prefer its cost/break-even disposition
and implement E2 independently. B2's initial cap remains seven CPU hours within
the shared exploration allowance. No tiny sequence-model setting is consumed.
