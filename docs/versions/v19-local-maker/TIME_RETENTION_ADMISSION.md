# Time-balanced retention: frozen execution contract

Does evenly covering source times preserve retrospective information better than
retaining only the newest sources at the same count? This implements the prepared
RETROSPECTIVE_TIME_BALANCE_PROTOCOL.md without selecting settings from outcomes.
The context-balanced result supplies a distinct question, not an optimization target.

Retain all 28,672 posteriors, 505,856 source candidates, eight development laws,
both evidence conditions, both draws and seven available checkpoint/horizon cells.
The 48 unavailable strata stay absent. Each draw has all 128 Cartesian identities.
Use the inherited endpoint alphabet, all four future contexts, every remaining
future time, and copy probabilities 0, 0.25, 0.5, 0.75 and 1. No fitting, additional
observations, confirmation lineages or random source subsampling is permitted.

The five states are full retention, recency at half/quarter time cutoffs, and
time-balanced rosters at those same counts. For k retained sources among n, sort
by unique source time and select ranks floor((j+0.5)*n/k), j=0,...,k-1. Use integer
arithmetic for these midpoint ranks; k=0 selects none. Contexts and endpoints are
unused in selection. No parameter search or alternative rounding rule is admitted.

Every source keeps its original uniform selection probability. Omitted source
likelihoods use the original uniform sixteen-maker prior, not history or future
group conditioning. The copied-endpoint histogram includes every source. The
teacher supplies exact laws, full posterior weights and source identities to an
evaluator-only reference. These are not public reader inputs or learned access.

Preserve all raw masks, source identities, report probabilities, exact support,
undefined error masks, proper squared regret, largest future-probability error,
group total variation, retained counts, forgotten mass and structural storage.
Float64 masses, int32 indices/counts and the shared prior table stay separate.
The copying-segment factorization reuses one independent-report direction across
copy probabilities. Timings describe this reference, not optimized compact-state
latency. Equal retained counts need not imply equal byte counts.

Before dispatch require scalar Bayes and materialized compact-state checks,
explicit expected one-hot losses, constant-law and full/certain-copy identities,
older informative source, all midpoint counts, irregular times, source permutation,
outcome/context-blind selection, and deliberate omitted-remainder corruption.
Require complete-support synthetic timing including serialization, all seven
structures and both source densities. Freeze source, plan, inputs, environment
and architecture before native outcomes. The existing queue executes original,
adjacent replay and extracted-source replay serially under its single owner.

The prospective inclusive cap is 3,600 CPU seconds, including implementation
verification, timing, failed attempts, three executions, independent reconstruction
and original-row regroup. Family/global ceilings and the protected reserve also
apply. A timing failure does not permit source sampling or changed scoring.

Numerical acceptance additionally requires an independently implemented source
selector, direct group/report Bayes numerators, independent bit schedules, explicit
proper-loss verification and storage recount. Separately regroup original rows
into 1,120 draw strata, 560 law strata and 70 population cells, retaining all fifty
metrics and both paired spaced-minus-recency contrasts. Both draws stay inside
each equally weighted law. No practical margin or confirmatory interval is frozen;
scope is descriptive constructed method, miniature - architecture untested beyond
this roster. Neither prediction nor reconstruction proves historical correspondence.

Prepared independent alternatives are two-report dependence and source-prior
sensitivity of fixed retention. Both require implementation, controls and timing;
their declarative protocols are not executable jobs.
