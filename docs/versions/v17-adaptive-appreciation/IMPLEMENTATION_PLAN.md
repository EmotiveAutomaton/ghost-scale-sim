## Viability and chosen implementation

The existing graphic and assembly executors provide genuine operations and
dependencies. Reuse them and the existing atomic-record/local-owner utilities.
A small common contract now separates finite probability forecasts, evidence
tiers, missing outputs, program validity, success and counted costs. A thin
`runners/run_v17.py` writes source-bound, resumable JSONL chunks. It calls no
old campaign stage and does not copy V16's campaign orchestration.

The first A slice compares the literal V16 repeated-fragment learner, episodic
retrieval with adaptation and primitive search on the sixteen-cell board.
Acquisition and supplied construction goals are legitimate maker assistance.
They are not artifact-only observer evidence. Repeated fragments retain the
original four-repetition threshold and one two-action definition. Memory retains
distinct successful acquisition episodes in acquisition order, within a 32-token
cap, and adapts only those retrieved actions to the public current state and
constraint. It does not quietly retain the full history for deployment.

All arms use the same executor, action order and search cost ceiling. Acquisition,
learning, storage, retrieval, proposal generation, binding, hypothetical execution,
actual execution and selection are separate accounts. These are declared discrete
operations and storage tokens, not equivalent CPU seconds. Actual process CPU and
elapsed time are recorded separately. Python/container/hash overhead is not
claimed to have a universal conversion to those tokens.

The discarded pilot considered 8, 32, 128, 512 and 2,048 operations. A rule fixed
in code selected three distinct budgets nearest pooled 20%, 50% and 80% solve
rates; lower ascending tuples break ties. It selected 8, 512 and 2,048 before the
scored namespace. The source-bound admission includes actual command resume,
retained-row equality and refusal of corrupt chunks. Frozen outputs cannot be
overwritten by a changed design or source.

The typed expression layer supports place, remove, sequence and zero-, one- and
two-argument definitions. Execution/cost equivalence is tested; this does not
claim that parameterized definitions have already been learned by Stitch.

## Sampling and interpretation

The initial screen uses 64 history draws in 16 constructor clusters per regime,
but only 57 distinct relevant private constructions per regime. Counterbalanced
orders and repeated histories are not new worlds. Across the three regimes
there are 192 public cases and 171 distinct private constructions. All constructors
permute one disjoint-pair motif architecture. Its status is **miniature —
architecture untested**; this first screen does not meet an architecture
generalization or confirmation claim.

Expand contrasting regions with actual independent construction support; do not
expand the Cartesian product or repeatedly sample to a desired significance.
Keep acquisition/test combinations disjoint, balance ordering, and retain
informative reversals. At most three future contrasts may be frozen for fresh
evaluation, with direction, estimand, sample size and one Holm family. The fresh
namespaces are reserved in the current packet designs and have not been used.
The initial bootstrap intervals are descriptive and are not equivalence tests.
